# Antenna（関心情報ダッシュボード）

複数の趣味・仕事・学習テーマについて、公式サイトやニュースサイト・YouTubeチャンネルなどをAIが自動で探し出し、関連する記事を継続的に集めて一覧表示するWebアプリです。記事へのリアクション（いいね／興味なし／保存）を重ねるほど情報源の優先度が調整され、使うほど自分専用のダッシュボードに育っていきます。

## 1. 対象ユーザーと課題

**利用者**：複数の関心テーマ（趣味・仕事・学習）について、継続的に情報収集したい個人。

**現在の課題**：関心テーマごとに公式サイト・ニュースサイト・SNSを自分で探して巡回する必要があり、テーマが増えるほど情報収集のコストが積み上がる。既存のRSSリーダーの多くも「情報源を自分で見つけて登録する」前提のため、情報源の発掘・選別はユーザー任せになりがちだった。

**改善したこと**：関心テーマを一言登録するだけで、AIが情報源の発掘から収集・要約・推薦までを代行するようにした。ユーザーは「何に関心があるか」を伝えるだけで、情報収集元を自分で探す手間が無くなる。

## 2. 主な機能

- **トピック登録**：自由記述で関心テーマを登録すると、AIが対象（人物・作品・分野など）を推定し、求めている情報の性質（最新情報か、体系的な情報か）まで判断する
- **情報源の自動発掘**：公式サイト・ニュースサイト・YouTubeチャンネル等の候補をAIが探索し、信頼度・関連度をスコアリングして提案する
- **記事の自動収集**：発掘した情報源から記事を継続的に取得し、タイトル・要約・関連度スコアを自動で付与する
- **リアクションによる学習**：記事へのリアクション（いいね／興味なし／保存／非表示）が情報源の優先度に反映され、使うほど推薦の精度が上がる
- **情報源の管理**：収集元ごとに取得方法・信頼度を手動編集でき、取得に何度も失敗する収集元は見直しを促す表示に切り替わる

## 3. 設計で工夫したこと

- **情報源の発掘はAI、採用の最終判断はユーザー**：AIは候補の提示とスコアリングまでを担当し、実際にその情報源を使うかどうかは常にユーザーが選べるようにした。AIに任せきりにしないことで、ユーザーが「なぜその記事が出てきたか」を追える設計にしている
- **ジャンルごとに安全性の基準を分けて管理**：音楽・グルメ・ペット・地域イベントなど33ジャンルについて、情報源として使ってよい範囲・注意喚起が必要な範囲を個別に定義できる仕組みを作った。例えばペット・動物ジャンルでは、健康・安全に関わる話題に「自己判断せず専門家へ確認を」という注意文を自動で付与する。中身を用意できていないジャンルに適当な警告文を出さないよう、設定が無いジャンルは汎用の確認文言にフォールバックする方針にしている（詳細: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)）
- **実機でしか再現しない不具合への対応**：公開後、Gmail等のメールアプリが安全確認のためリンクを事前に読み込んでしまい、1回限りの確認トークンが本人のタップ前に消費される不具合を実機検証で発見した。認証確認をリンク方式から、画面に確認コードを直接入力する方式へ切り替えて解決した

## 4. 技術・動作確認

| 領域 | 技術 |
|---|---|
| フロントエンド | Next.js 16 (App Router) / React 19 / TypeScript / Tailwind CSS 4 |
| バックエンド | Supabase（PostgreSQL / Auth / Row Level Security） |
| AI | Anthropic Claude API |
| 検索 | Brave Search API |
| メール配信 | Resend（カスタムSMTP） |
| ホスティング | Vercel |
| エラー監視 | Sentry |
| モバイルアプリ | Capacitor（本番Webを iOS ネイティブアプリとしてラップ） |

```bash
npm install
cp .env.local.example .env.local  # Supabase / Anthropic / Brave SearchのAPIキーを設定
npm run dev
```

[http://localhost:3000](http://localhost:3000) で確認できます（必要な環境変数は`.env.local.example`参照）。本番は https://www.myantenna.app で実際に動作しています。

**ソースコードの主要構成**:

```text
app/(marketing)/   トップページ・利用規約・プライバシーポリシー
app/(auth)/        ログイン・新規登録・パスワード再設定
app/(app)/         マイページ・トピック管理・収集元管理・保存記事・設定
lib/ai/            AI呼び出し（Claude）のラッパー群
lib/genres/        ジャンル別の安全機構・収集ポリシー設定
lib/recommendation/ 推薦カード選定ロジック
supabase/migrations/ DBスキーマ
```

詳細設計（データモデル・AIパイプラインの各段階・ジャンル別安全機構の仕組み）は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) にまとめています。利用規約・プライバシーポリシーは本番環境内（[/terms](https://www.myantenna.app/terms)・[/privacy](https://www.myantenna.app/privacy)）に掲載しています。

## 5. AI利用について

開発の要件整理から実装・デバッグ・本番運用まで、Anthropic Claude（Claude Code）を開発支援として利用しています。

| 工程 | AIに任せたこと | 自分で判断・確認したこと |
|---|---|---|
| 要件整理 | 機能の実現方法の選択肢の洗い出し | 実際に採用する方針の決定 |
| 設計 | 実装方針・データモデルのたたき台作成 | 設計の妥当性の確認、方針の最終決定 |
| 実装 | コード生成・既存コードの修正 | 生成コードのレビュー、ビルド・型チェックの実行確認 |
| デバッグ | ログ・ネットワーク通信の調査、原因の仮説立て | 実機での再現確認、修正内容の実機検証 |
| 運用 | デプロイ作業・App Store Connect設定変更の手順案内 | 実際の操作実行、画面共有による動作確認 |

AIの提案や「修正できました」という報告をそのまま採用するのではなく、**実際にビルドが通るか・実機で動くかを都度確認した上で採用**する、という進め方をしています。

なお、アプリ内のトピック分類・情報源発掘・推薦カード生成はAnthropic Claude APIを実行時に呼び出して実現している、**アプリの機能そのもの**です（上記の開発支援としてのAI利用とは別軸）。
